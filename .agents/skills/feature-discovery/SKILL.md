# 기능 아이디어 발굴

[공통 규칙](../../../AGENTS.md), [통합 조정](../../../docs/workflows/orchestrator.md), [Jira](../../../docs/providers/jira.md), [리뷰 기준](../../../docs/review/orchestrator.md)을 읽는다. 요청과 루트 설정에서 프로젝트와 공식 원본을 확인한다.

1. 공통 절차대로 Confluence 논의와 후보 목록을 확인한다. 사용자 제안·미결 사안을 우선 검토하고 공식 요구사항·계약, 관련 구현 영역, 기존 Jira 후보·작업 및 GitHub PR을 대조한다. 필수 자료 조회 실패를 중복 없음으로 취급하지 않는다.
2. 목적·기대 효과·기존 기능과의 차이·미결 사항·출처가 명확한 후보만 선정한다. 동일 요청에서 재사용되는 기존 후보까지 최대 3개다.
3. 후보 상태와 Candidate ID를 포함해 Jira에 등록하고 재조회한다. 결과가 불명확하면 같은 ID로 조회한 뒤 처리한다. 분석 전용 요청에서는 제안만 보고한다.
4. 후보별 근거·링크·미결 사항과 보류 사유를 보고한다. 승인이나 다음 단계의 실행은 사용자 요청 범위를 따른다.
