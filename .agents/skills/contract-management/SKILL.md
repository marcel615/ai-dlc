# 공식 계약 변경 관리

[공통 규칙](../../../AGENTS.md), [통합 조정](../../../docs/workflows/orchestrator.md), [Jira](../../../docs/providers/jira.md), [리뷰 기준](../../../docs/review/orchestrator.md)을 읽는다. 지정 계약 작업과 루트 설정의 공식 경로·기본 브랜치 SHA를 확인한다. [계약 작업 상태와 마무리](../../../docs/workflows/orchestrator.md#계약-작업-상태와-머지-후-마무리)에 따라 실제 협의 시작, PR 연결, 머지 확인 단계별 상태를 갱신·재조회한다.

1. 실제 명세·구현·소비자와 호환성을 대조한다. 영향과 대안, 전환 순서 및 복구 제약을 정리하고 명세 수정에 대한 사용자 승인 또는 해당 회차의 명시적 위임을 확인한다.
2. 같은 변경의 기존 Specs Task와 영향받는 구현 작업을 조회한다. Jira 절차대로 필요한 작업·차단 관계만 생성하거나 재사용하고 재조회한다. 협의·결정의 사유와 출처를 관련 Jira 본문 및 설정된 Confluence 계약 논의에 필요한 범위만 기록한다.
3. 최신 원격 기본 브랜치 SHA에서 Specs 작업 브랜치를 만들고 이름에 설정된 접두사와 Jira 키를 포함한다. 구현 작업이 미완료라면 원래 변경을 그대로 두고 깨끗한 별도 worktree에서 Specs 작업을 진행한다. 승인된 공식 파일을 변경하고 계약 일관성과 소비자 영향 범위를 검증한다. 설정된 기본 브랜치로 Specs PR을 열고 PR 링크를 Jira에 기록·재조회한다. 독립 실행의 머지는 사용자가 담당한다.
4. 마무리에서는 PR이 설정된 기본 브랜치에 실제 머지됐는지 확인하고 해당 브랜치의 공식 원본 SHA, 차단 해제 조건 및 재상세화 필요성을 재조회한다. 계약 작업만 완료 처리하고 영향받는 구현 작업의 상태를 보존한다.
